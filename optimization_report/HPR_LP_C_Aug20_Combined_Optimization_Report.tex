\section{Executive summary}

The Aug-20 source snapshot was found to differ from the Aug-19 baseline in
exactly one production file: the automatic sparse-matrix backend selection
policy.  The Aug-19 presolver candidate differs from that same baseline in
exactly seven GPU-presolver files.  The final local candidate starts from the
Aug-20 source and replaces only those seven files with their byte-exact,
previously validated Aug-19 fast-presolver versions.  Consequently, the
Aug-20 backend policy is preserved byte-for-byte and no unrelated source is
changed.

Prior evidence supports the two components separately.  The Aug-19 adaptive
presolver campaign matched all recorded solution-path and postsolve fields on
49 of 49 cases and reduced presolve sGM10 from 0.463171 seconds to 0.213816
seconds, a 2.1662x speedup.  The supplied Aug-20 CSV reports solve-time sGM10
of 5.603869 seconds versus 6.107002 seconds in the separate Aug-19 baseline
campaign, but those samples are unmatched and ten iteration counts differ.
They are diagnostic component evidence only.

The source merge is complete.  A CUDA build and matched combined run were not
completed: the local ARM64 host has no \texttt{nvcc}, and transfer of the
private candidate to the remote H100 validation host was not authorized in
this task.  Therefore the combined numerical verdict is inconclusive, its
performance is not assessed, and the release gate is hold.

\section{Testing and reproduction instructions}
\label{sec:reproduction}

\subsection{Dependencies}

Use Linux x86-64 with an NVIDIA CUDA GPU, GNU Make, g++, zlib development
headers, and a CUDA toolkit compatible with the target architecture.  The
prior H100 build used \texttt{GPU\_SM=90}.

\subsection{Build original and candidate}

The following are exact planned commands from the Aug-20 dated folder.  They
were not executed in this task.

\begin{lstlisting}[style=reportcode]
make -C HPR-LP-C-SpMVOp-05f9150-source GPU_SM=90 -j16
make -C HPR-LP-C-SpMVOp-05f9150-presolve-combined GPU_SM=90 -j16
\end{lstlisting}

\subsection{Focused correctness diagnostics}

Run baseline and candidate separately with the same physical GPU mapped to
logical device 0.  The first cases must include \texttt{FOME13.mps.gz},
\texttt{dlr2.mps.gz}, \texttt{degme.mps.gz}, and \texttt{s82.mps.gz}.
The exact solver options are:

\begin{lstlisting}[style=reportcode]
-i INPUT.mps.gz --device 0 --time-limit 1000 --tol 1e-6 \
  --check-iter 150 --max-iter 2147483647 --presolver gpu \
  --gpu-folding true --reduced-matrix true \
  --auto-memory-policy false
\end{lstlisting}

After focused diagnostics, run the frozen 49-case list as serialized
baseline/candidate pairs.  Diagnostics and timing must be separate.  Timing
requires multiple synchronized alternating pairs, identical logging, and a
captured GPU UUID and competing-process snapshot.

\subsection{Reproduce source identities}

Run from each source root, excluding report artifacts:

\begin{lstlisting}[style=reportcode]
find . -type f ! -path './optimization_report/*' \
  ! -name '.DS_Store' -print0 | LC_ALL=C sort -z | \
  xargs -0 shasum -a 256 | shasum -a 256

shasum -a 256 \
  optimization_report/aug20_to_combined_source.patch
\end{lstlisting}

\section{Known limitations}

\begin{itemize}
  \item No combined CUDA binary was built; the local host has no \texttt{nvcc}.
  \item No combined diagnostic, complete iterate-vector comparison, memory profile, or timing pair exists.
  \item Remote source transfer was not authorized in this task, so no private solver source was uploaded for validation.
  \item The Aug-19 fast engine previously changed one \texttt{FOME13} reduced-active-set event.  The Aug-19 handoff used a path-exact compatibility engine for that case; the uniform combined source has not yet been checked or adapted.
  \item The supplied Aug-20 CSV is a single campaign without a matching manifest in the dated folder.  Its timing is diagnostic, and ten iteration counts differ from the separate Aug-19 baseline campaign.
  \item The 49 Hans inputs are not included.  Their current hashes and availability must be recovered before a new campaign.
  \item No confidence interval, per-instance regression guardrail, or combined end-to-end speedup can be reported.
\end{itemize}
